# Сравнение методов переноса смещения

Одна задача для всех методов: найти бинарный шаблон длины 12 в последовательности
длины 24. Используется перенос генератора из `assets/conv_data_v2.ipynb`,
описанный в [`../_pattern_transfer/README.md`](../_pattern_transfer/README.md).
Учителя обучаются на одном исходном шаблоне, студенты — на других шаблонах.
Целевая модель всегда один и тот же MLP.

Зависимости: `torch`, `matplotlib`. Команды из корня репозитория:

```bash
python experiments/method_comparison/experiment.py
python experiments/method_comparison/plot_results.py
```

По умолчанию используется CUDA. Для CPU передайте `--device cpu`.
JSON сохраняется в `results/method_comparison/metrics.json`, графики — рядом.
Относительные пути отсчитываются от текущей рабочей директории.

## Методы

| Название | Обучение студента |
| --- | --- |
| `baseline` | Только BCE по целевым меткам |
| `known_shift` | BCE + штраф инвариантности к равномерной смеси четырёх сдвигов |
| `learned_cnn`, `learned_mlp` | То же, с распределением сдвигов, обученным по учителю |
| `cnn_init`, `mlp_init` | Encoder после воспроизведения скрытых активаций учителя; далее только BCE |
| `cnn_prior`, `mlp_prior` | Та же инициализация + штраф к исходным параметрам encoder |
| `random_prior` | BCE + штраф к случайной инициализации encoder |
| `untrained_cnn_init`, `untrained_mlp_init` | Инициализация из активаций необученного учителя |
| `untrained_cnn_prior`, `untrained_mlp_prior` | Та же инициализация + штраф к параметрам encoder |
| `shuffle` | BCE + штраф инвариантности к перестановке координат; отрицательный контроль |

Всего 14 вариантов. `--teachers cnn` оставляет варианты с CNN и общие контроли.
Комбинации разных способов переноса не используются.

Переиспользуются существующие `learn_policy`, `consistency_penalty`,
`distill_features`, `parameter_prior` и `shuffle_coordinates`, а также общий
генератор, модели и цикл обучения. Предыдущие эксперименты не изменяются.

Известный сдвиг изображения адаптирован к одномерной последовательности:
сдвиг на один элемент влево/вправо с заполнением `-1`/`+1`.
Все штрафы инвариантности сравнивают **вероятности после sigmoid**:

```text
loss = BCE(logits(x), y) + consistency_weight * E_A |p(x) - p(A(x))|
```

Для четырёх сдвигов ожидание считается точно. Для `shuffle` на каждом шаге
выбирается независимая перестановка для каждого объекта. Перестановка разрушает
структуру шаблона, поэтому здесь проверяется эффект неверного смещения.
Cross-entropy считается только на исходных входах; градиенты штрафа проходят
через оба предсказания.

Учитель и признаки обучаются как в отдельных экспериментах. Encoder студента
воспроизводит активации учителя, нормированные на их RMS на source train.
Классификационная голова не переносится. Параметрический штраф имеет вид:

```text
loss = BCE(logits(x), y) + prior_weight * mean((encoder_params - center)²)
```

## Протокол

По умолчанию: три seed (`0`, `1`, `2`), три целевых шаблона на seed, размеры
целевого train `32`, `128`, `512`, test по 512 примеров на задачу. Внутри каждого
seed исходный и целевые шаблоны различаются. Между seed наборы задач меняются.
Малые выборки — общие для методов префиксы большого train.

В пределах seed, задачи и размера выборки совпадают данные, начальная голова,
порядок батчей, Adam, learning rate и число шагов целевого обучения.
Encoder меняется только в методах с переносом признаков. Подготовка encoder
использует только source train; source test нужен для отчётных метрик.
Учитель, политика и начальный encoder готовятся один раз на seed и используются
для всех целевых шаблонов и размеров выборки.

По умолчанию учителя обучаются 50 эпох, признаки — 50 эпох, студенты — 50 эпох,
политика — 200 шагов. Веса consistency и prior равны `1`, вес энтропии `0.01`.
Веса задаются независимо через CLI и не подбираются по целевому test.
Одинаковое число шагов не означает одинаковое время: аугментации требуют
дополнительных прямых проходов.

## JSON и графики

- `config`, `methods` — параметры запуска и список вариантов.
- `runs` — шаблоны каждого seed, истории учителей, вероятности политик,
  ошибки воспроизведения признаков и время подготовки по стадиям.
- `results` — истории студентов с `seed`, `task`, `train_size`, `method`.
  Истории включают BCE, accuracy исходных и сдвинутых входов, отклонение
  вероятностей и обучающие потери. Эпоха 0 — до целевого обучения.
- `target_fit_seconds` — целевое обучение со всеми эпохальными оценками,
  без создания модели и отдельной финальной диагностики.
  `diagnostic_seconds` — время этой дополнительной диагностики.
  Для CUDA время измеряется с синхронизацией устройства.

Время учителя, политики и воспроизведения признаков хранится отдельно в `runs`:
оно разделяется между несколькими целевыми запусками и не прибавляется к каждому
из них. JSON обновляется после подготовки каждого seed и каждого целевого запуска.

Основные тестовые сдвиги фиксированы и сохраняют истинную метку.
Аугментации при обучении не фильтруются по истинному шаблону. Для `known_shift`,
`learned_*`, `shuffle` дополнительно сохраняется `augmentation_metrics`:
доля сохранённых меток, доля изменившихся входов, accuracy по истинным новым
меткам преобразованных входов и отклонение вероятностей. Для сдвигов это точное
ожидание по четырём вариантам, для перестановок — одна фиксированная версия
каждого test-примера. Истинный шаблон используется только для диагностики.

`sample_efficiency.png` показывает итоговые accuracy, BCE и отклонение
вероятностей по размеру train. `curves_n*.png` — те же метрики по эпохам.
Сначала усредняются целевые задачи внутри seed, затем значения между seed.
Заливка — ± одно выборочное стандартное отклонение **между средними seed**,
не доверительный интервал. При одном seed заливка имеет нулевую ширину.
Accuracy в JSON — доля от 0 до 1, на графиках — проценты.

Графики требуют завершённых результатов всех seed, задач и размеров для
выбранных методов; незавершённый JSON не усредняется как полное сравнение.

```bash
python experiments/method_comparison/experiment.py --seeds 0 1 2 --consistency-weight 0.1 --prior-weight 10 --output results/method_comparison/other_weights.json
python experiments/method_comparison/plot_results.py results/method_comparison/other_weights.json --output-dir results/method_comparison/other_weights --methods baseline known_shift learned_cnn cnn_init cnn_prior shuffle
```

`--seeds` задаёт точный список seed. Если его нет, используются `--seed`,
`--seed + 1`, `--seed + 2`. Оценивать нужно качество, инвариантность и сохранение
меток вместе: маленькое отклонение само по себе не означает хорошую модель.
